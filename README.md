# 検出カウンター

共有した画面（ブラウザタブ・ウィンドウ・モニター）の中から、ユーザーが登録した画像（検出対象）を探し、
その出現回数を数える、汎用的な画像検出カウンターです。

画面キャプチャ・画像処理・カウント処理・設定保存は、すべてこのアプリのHTML/CSS/JavaScript/WebAssembly
（OpenCV.js）だけで完結します。サーバー処理、外部API、外部への画像アップロードやデータ送信は一切行いません。

## 1. これは何のためのアプリか

**特定のゲームや特定の業務アプリ専用ではありません。** 画面上に現れる「何らかの画像」の出現回数を、
ユーザー自身が登録した画像を基準にカウントする汎用ツールです。

想定される利用例（一例です。これ以外の用途にも自由に使えます）:

- ゲームの勝利・敗北・ラウンド終了などの結果表示を数える
- 特定の通知アイコンが表示された回数を数える
- アプリの完了表示・成功表示が出た回数を数える
- 配信画面や動画に特定のロゴ・カットインが現れた回数を数える
- 業務アプリで特定の状態表示が出た回数を記録する
- テスト作業中に特定のダイアログが表示された回数を数える
- プレゼン資料や教材で、特定のスライド要素が登場した回数を数える

このアプリは、**文字認識(OCR)でも、一般的な物体認識(機械学習モデルによる物体検出)でもありません。**
ユーザーが登録した画像と、共有画面の一部を画素単位で比較する「テンプレートマッチング」を行うツールです。
登録していない物体や、形状が大きく変わる対象を自動的に理解するものではありません。

## 2. 対応ブラウザ

- Google Chrome（最新版）
- Microsoft Edge（最新版）
- その他Chromium系ブラウザ

Firefox・Safariでは、画面共有API・フレームコールバックAPI・OpenCV.jsの挙動差により、
一部機能が制限される場合があります。非対応の機能がある場合は、アプリ起動時にその旨を案内します。

画面共有機能（`getDisplayMedia`）を使うため、**HTTPS環境（またはlocalhost）が必要です。**
GitHub PagesはHTTPSで配信されるため、公開後はそのまま利用できます。

## 3. GitHub Pagesへの公開手順

1. このリポジトリをGitHubへpushします。
2. `vendor/opencv.js`（必要なら `vendor/opencv_js.wasm` も）を配置します。手順は [vendor/README.md](vendor/README.md) を参照してください。
3. GitHubリポジトリの `Settings` → `Pages` を開きます。
4. `Source` を `Deploy from a branch` にし、公開したいブランチ（例: `main`）とルートフォルダ（`/`）を選択して保存します。
5. しばらくすると `https://<ユーザー名>.github.io/<リポジトリ名>/` でアプリが公開されます。
6. 公開後、実際にブラウザでアクセスし、画面共有と検出対象登録が正しく動くことを確認してください。

## 4. ローカルでの起動方法

`getDisplayMedia` はセキュアコンテキスト（HTTPSまたはlocalhost）でのみ動作するため、
`file://` として直接HTMLファイルを開くのではなく、簡易サーバー経由で開いてください。

```bash
# Pythonがある場合
python3 -m http.server 8080

# Node.jsがある場合(npxのみで追加インストール不要)
npx serve .
```

起動後、ブラウザで `http://localhost:8080` を開きます。ビルド工程は不要です。

## 5. 基本的な使い方

最初に開くページ(`index.html`)には、「検出カウンターを開く」ボタンだけがあります。
これを押すと、操作専用の別ウィンドウ(`app.html`)が開きます。**画面の選択・検出対象の登録・
カウントの開始まで、すべてこの専用ウィンドウの中で行います。** 最初のページのタブはそのまま
閉じてしまって構いません(ポップアップブロックが働いている場合は、このサイトからのポップアップを
許可してください)。

専用ウィンドウの中では、画面上部の「ステップ1〜3」に沿って進めれば、画像処理の知識がなくても
利用を開始できます。

### ステップ1: 検出したい画面を選択

「画面を選択」ボタンを押すと、ブラウザ標準の共有ダイアログが開きます。
**このアプリ自身のタブではなく、検出したい内容が映っている画面・ウィンドウ・タブを選んでください。**

- 「共有する画面を変更」で、共有対象を切り替えられます（登録済みの検出対象・カウント・設定は維持されます）。
- 「画面共有を停止」で、共有と解析を安全に停止します。
- ブラウザ側の共有停止操作（ブラウザのバー等）を行った場合も、自動的に安全な状態へ戻ります。
- 共有する画面の解像度や表示倍率が変わると、検出精度が変化する場合があります（後述）。

### ステップ2: 検出対象を登録

2つの方法があります。

**方法A: 共有中の画面から切り取る（推奨）**

1. 「現在の画面から登録」を押すと、映像が一時停止します。
2. プレビュー上をドラッグして、検出したい部分を四角で囲みます。
3. 切り取られた画像のプレビューと、対象名の入力欄が表示されます。
4. 名前を確認・変更し、「検出対象として追加」を押します。

**方法B: 画像ファイルから登録**

「画像ファイルを選択」から、PNG・JPEG・WebPなどの画像ファイルを複数選択できます。
ファイル名が対象名の初期値になりますが、後から変更できます。

登録した検出対象は一覧に表示され、名前変更・有効/無効切り替え・カウントリセット・削除ができます。

### ステップ3: カウントを開始

「カウントを開始」を押すと、共有画面の中から登録した検出対象を探し始めます。
検出対象が画面に現れると、対象カードが光り、カウントが1増え、画面右上に通知が表示されます。
「カウントを停止」でいつでも解析を止められます。

「カウントを開始」を押すと、この専用ウィンドウは自動的に、各検出対象のカウント数だけを表示する
小さい表示に切り替わります(同じウィンドウが小さくなるだけで、新しいウィンドウは増えません)。
小さい表示の「⚙ 設定を表示」を押すと、いつでも元の大きさ・元の画面に戻って設定を変更できます。
この小さいウィンドウを画面の隅に表示したままにしておけば、共有元のウィンドウを操作していても
カウントは続きます。ただし、このウィンドウ自体をOSの機能で最小化すると、ブラウザの仕様上
カウントの間隔が空いたり止まったりすることがあります(その場合はウィンドウを再度表示すれば
すぐに復帰します)。

## 6. 正しく検出するためのコツ

- 毎回ほぼ同じ見た目になる部分を選ぶ（時刻・数字・ユーザー名・アニメーション・動画・点滅・半透明・
  ランダムな背景などは避ける）
- 対象の周囲に余白を入れすぎない
- 共有画面の解像度とウィンドウサイズを変えない（変えると再登録が必要になることがあります）
- 誤検出する場合は、探索範囲を狭める
- 検出されない場合は、詳細設定の検出開始閾値を少し下げる
- 誤検出する場合は、検出開始閾値を上げる
- 小さすぎる画像ではなく、特徴が分かる範囲を選ぶ
- 似た画像が画面内に複数ある場合は、より特徴的な部分を含める

「共有中の画面から登録」で切り取る方法は、解析時と同じ解像度・拡大率で登録できるため、
ファイルから読み込む方法よりも検出精度が安定しやすいです。

## 7. カウントされる「出現イベント」の定義

このアプリが数えるのは、解析フレームごとの検出回数ではなく、**対象画像が「非表示の状態から表示された
状態へ変化した回数」**です。

```text
対象が表示されていない
  ↓
対象が表示された     ← ここでカウントを1増やす
  ↓
対象が表示され続けている ← 増やさない（同じ出現の継続）
  ↓
対象が消えた
  ↓
（再び表示されたら、新しい出現として次のカウント）
```

対象が数秒間表示され続けても1回だけカウントし、一度消えて再び表示されれば新しい出現として
再度カウントします。

## 8. 検出開始閾値・検出終了閾値・連続フレーム数（ヒステリシス）

閾値付近でのチラつきによる誤カウントを防ぐため、次の4状態で管理しています。

```text
未検出 → 検出候補 → 検出中 → 非検出候補 → 未検出 ...
```

- **検出開始閾値**: この値以上の類似度が、指定した連続フレーム数続くと「検出中」になり、カウントされます。
- **検出終了閾値**: 検出開始閾値より低い値です。検出中にこの値を下回る状態が、指定した連続フレーム数
  続いて初めて「未検出」に戻ります。
- 検出中に類似度が一瞬下がっても、検出終了閾値を下回らない限り、あるいは連続フレーム数に達しない限り
  「検出中」は維持されます（= 表示され続けている間に何度もカウントされることを防ぎます）。
- **クールダウン**: 状態管理を補助する追加の防止策です。一度カウントしてから指定時間内は、たとえ
  状態遷移が発生しても再カウントしません。クールダウン単体で重複防止を行っているわけではありません。

閾値は「検出終了閾値 < 検出開始閾値」の関係を保つ必要があります。この関係が崩れる値を入力した場合、
自動的に補正されます。

## 9. 探索範囲の使い方

初期状態では画面全体を解析対象としますが、「探索範囲」パネルで「範囲を指定」を選び、
「範囲を選択」からプレビュー上をドラッグすると、その範囲だけを解析するようになります。

探索範囲は、キャプチャ画面の幅・高さに対する**比率**でも保存されるため、キャプチャ解像度が
多少変化しても、同じような位置を探索し続けられます。ただし、共有画面のレイアウトが大きく変わった
場合は、範囲を再設定してください。

「探索範囲を画面に表示する」のチェックを外すと、プレビュー上の範囲表示を非表示にできます
（解析自体には影響しません）。

## 10. 画面解像度・表示倍率・ウィンドウサイズを変えると起きること

`cv.matchTemplate()` は、登録画像と画面上の対象のピクセルサイズが一致しているほど精度が高くなります。
共有画面の解像度、ブラウザのズーム、ウィンドウサイズ、OSの表示スケールなどを変更すると、
登録済みの検出対象が同じ大きさで映らなくなり、検出できなくなることがあります。
その場合は、検出対象を同じ条件下で再登録するか、詳細設定の「スケール探索」を有効にしてください。

## 11. すべての処理がブラウザ内で完結すること

- 画面キャプチャ映像、登録した検出対象画像、カウント結果、設定、履歴は、すべてこのブラウザの中
  （メモリおよびIndexedDB）だけで扱われます。
- サーバーへのアップロードや外部APIの呼び出しは一切行いません。コード内にも `fetch` /
  `XMLHttpRequest` / `WebSocket` による外部送信処理は含まれていません。
- OpenCV.js・CSS・JavaScript・フォントは、すべて同一オリジン（GitHub Pages上の同じサイト）内の
  ファイルから読み込みます。CDNやアクセス解析、外部フォントは使用していません。

## 12. 保存されるデータと持ち運び方

- ページを再読み込みすると、登録済みの検出対象・カウント・設定・履歴はIndexedDBから自動的に
  復元されます（画面共有はブラウザの仕様上、再読み込み後に自動再開できないため、再度「画面を選択」
  してください）。
- 「設定を書き出す」で、検出対象画像を含む設定一式をJSONファイルとして保存できます。
  「設定を読み込む」で、そのJSONファイルから復元できます。
- 不正なJSONファイルを読み込んでも、アプリ全体が壊れないよう、内容を検証してから反映します。
  読み込めない項目はスキップし、致命的に壊れている場合はエラーメッセージを表示します。

## 13. 制限値（初期値）

| 項目 | 初期値 |
|---|---|
| 検出開始閾値 | 0.85 |
| 検出終了閾値 | 0.70 |
| クールダウン | 3000ms |
| 解析頻度 | 2回/秒 |
| 検出確定までの連続フレーム数 | 2 |
| 検出終了までの連続フレーム数 | 2 |
| 解析画像の縮小率 | 50% |
| 最大検出対象数 | 20個 |
| 最大画像ファイルサイズ | 10MB |
| 最大画像辺長 | 4096px |

これらは詳細設定からいつでも変更できます。

## 14. 既知の制約

- 文字認識・一般物体認識ではなく、登録画像との画素比較（テンプレートマッチング）です。
- 登録時と大きく異なる解像度・拡大率・配色で表示された対象は検出できないことがあります。
- 動く背景、時刻表示、点滅、半透明部分を含む対象は精度が下がります。
- ページを再読み込みすると画面共有は解除されます（ブラウザの仕様上の制約です）。
- 小さい表示にしたウィンドウをOSの機能で最小化すると、ブラウザの仕様上、カウント処理の間隔が
  空いたり一時的に止まったりすることがあります（ウィンドウを再表示すればすぐに復帰します）。
- OCR・音声認識・動画ファイル解析・クラウド保存・複数PC間同期・ユーザーアカウントには対応していません。

## 15. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 「検出カウンターを開く」を押しても専用ウィンドウが開かない | ブラウザのポップアップブロック機能が働いています。このサイトからのポップアップを許可してください。 |
| 「画像処理機能を読み込んでいます...」から進まない / エラーになる | `vendor/opencv.js` が正しく配置されているか確認してください。詳細は [vendor/README.md](vendor/README.md)。 |
| 画面共有ダイアログが出ない | ブラウザがgetDisplayMediaに対応しているか、HTTPS（またはlocalhost）で開いているか確認してください。 |
| 共有を許可したのに何も映らない | 共有対象のウィンドウ・タブが閉じられていないか確認し、「共有する画面を変更」からやり直してください。 |
| 検出対象が画面に映っているのに検出されない | 検出開始閾値を少し下げる、探索範囲を広げる、対象を画面から直接再登録する、のいずれかを試してください。 |
| 関係ない部分まで検出されてしまう(誤検出) | 検出開始閾値を上げる、探索範囲を狭める、対象画像により特徴的な部分を含める、のいずれかを試してください。 |
| カウントが増え続けてしまう | 検出終了閾値・連続フレーム数・クールダウンを見直してください。閾値付近の値が不安定な可能性があります。 |
| 設定の読み込みでエラーになる | このアプリの「設定を書き出す」で作成したJSONファイルであるか確認してください。 |

## 16. メモリリークを確認する方法

詳細設定の「デバッグ表示」を有効にすると、JSヒープ使用量（対応ブラウザのみ）や解析FPS、
1フレームあたりの処理時間などが表示されます。数十分程度カウントを継続し、この値が右肩上がりに
増え続けないことを確認してください。ブラウザの開発者ツール（タスクマネージャーやPerformanceタブ）
でメモリ推移を確認する方法も有効です。内部的には、解析ループで生成した `cv.Mat` を
`try / finally` で必ず解放し、検出対象ごとのテンプレートは登録時・設定変更時にのみ再生成して
使い回す実装になっています。

## 18. ファイル構成

```text
index.html          入口ページ。「検出カウンターを開く」ボタンのみを持つ
app.html             アプリ本体の画面全体のマークアップ(index.htmlから専用ウィンドウとして開く)
style.css            スタイル（外部フレームワーク不使用）
js/landing.js         index.html用: app.htmlを専用ウィンドウとして開く処理のみ
js/state.js          中心的なアプリ状態(ストア)とデータモデル
js/capture.js         画面共有(getDisplayMedia)のライフサイクル管理
js/opencvLoader.js    vendor/opencv.js の動的読み込み
js/regionSelect.js    ドラッグによる矩形範囲選択(切り取り・探索範囲で共用)
js/detection.js       テンプレートマッチングと検出状態のヒステリシス管理
js/storage.js         IndexedDB保存 / JSON書き出し・読み込み
js/history.js         カウント履歴の生成・CSV/JSON書き出し
js/ui.js              画面描画(DOM操作)
js/main.js            app.html用: 上記モジュールをつなぐ結線・イベント処理
vendor/opencv.js      OpenCV.js本体（別途配置。vendor/README.md参照）
vendor/opencv_js.wasm 同上(ビルドにより不要な場合あり)
```

`index.html` はGitHub Pagesのルート(`/`)として配信する必要があるため、あえてこのファイル名のままに
しています。実際の画面共有・検出処理はすべて `app.html` 側で行われます。

ビルドツールやNode.jsのインストールは不要です。ファイルをそのままGitHub Pagesへ配置すれば動作します。
